# Agent评测：检查它有没有把事情办对

这套评测检查取证、计算、解释、提醒和记忆行为。股票后来涨跌是否符合预测，另外统计，不能代替Agent行为评测。

## 交付内容与当前状态

36个合成事件，每个都有用户状态、证据快照、预期输出、错误行为、参考过程和结构化断言。JSONL中actual_run=null、status=not_run；没有模型实测成绩。工具名fixture.*只是测试约定，不是当前产品已有接口。

Excel的“评测事件”前半部是新设计，末尾保留原12条历史行情判断作附录。原60条异动记录不改写。所有样本都是公开设计种子题；接入后需要另留未见事件作测试集。

## 一条题目怎么跑

1. 固定截止时间、市场、数据口径、用户偏好和规则版本，把证据快照交给Agent。只开放沙箱工具，不发真实通知、不改真实记忆。
2. 保存Agent实际读取了什么、调用参数和返回、输出的事件、提醒意图以及最终规则/记忆状态。保存外显行为即可，不索取内部思维链。
3. 用assertions逐项比较结构化实际输出；JSON里的数字按各字段声明精度比较，null与0必须区分。无需强制参考过程的唯一调用顺序。
4. 人工复核回答是否说清事实、关系和未知项，以及must_not行为是否出现。自然语言不能仅靠关键词匹配打分。
5. 只有拿到真实执行记录后才写actual_run。输入或工具未接好标blocked；运行后行为错误标failed；不能把未运行题记为通过。

## 怎么判分

硬性失败项：偷看未来；捏造数据/来源；未经授权改规则、写记忆或外发。这些出现任一项，该题失败，文案流畅不能抵消。

其余检查分五项，各0/1/2分：①证据与时间；②计算与分类；③用户相关性与范围；④通知/去重/状态变化；⑤表达与不确定性。0=关键错误或漏项，1=主要正确但有缺漏，2=完整符合该题要求。不适用项记N/A；有效得分=所得分÷适用项满分。

单题通过条件：全部必需结构化断言满足、无硬性失败、适用项得分≥80%。每题都要求的assertions使用equals；参考答复只是合格表达示例，不要求逐字一致。

运行集通过率=通过题数/实际运行完成题数；另报已运行覆盖率=(通过+失败)/计划题数，blocked与not_run分开列。不用遗漏难题来美化通过率。

## 信噪比应该怎么评

先由独立评审标注固定监测范围内哪些事件确实值得提醒，再和Agent输出逐事件匹配。告警准确率=正确提醒/全部提醒；重要事件召回率=发现的重要事件/全部标注重要事件；另看每用户每日提醒数、同事实重复提醒数和提前量。

原表155个股票交易日与60条异动不是同一种统计对象，60/155不能叫降噪率。提醒变少也可能是漏报；原12条历史预测的命中率更不能冒充信噪比。没有独立标签时，本版不提供这些成绩。

## 先做哪些验证

第一批可对照现有规则：E01—E04（日线量价）、E21（档位差异）、E27—E29（结算）。这些仍需测试适配器，不能仅看源码就记通过。
第二批验证关键缺口：E07（日线冒充盘中）、E10（跨市场关系）、E22（单证券开关）、E24—E25（记忆有效期与删除）、E31（资料注入）。

每次发布固定代码版本、规则版本、模型/提示词版本和数据快照；同一事件及其改写放同一数据划分，避免泄漏。按A股、港股、美股、时段和缺失数据情况分别报结果；设计题不等于真实市场评测集。

## 运行输入与答案隔离

只把user_state、evidence、as_of、market、rule_version和任务范围送入Agent。expected_output、answer_example、assertions、acceptance_summary和reference_trace只能给评判器，不能作为Agent输入。每题仅测signals指定的规则与当前任务；不把本项未提醒理解为整只股票没有风险。日终字段均取截止前上一完整交易日。

数值精度：百分数按百分点数值存储（8表示8%）；倍数直接存数值。turnover_multiple_rounded先四舍五入到两位再比较，其余断言使用精确值；阈值判断前不取整。分母为0时不输出比例。

actual_run接入后至少保存run_id、代码/规则/模型/提示词版本、开始结束时间、工具调用ID/参数/返回/错误、最终输出和状态变化、逐项断言结果、人工分项分数及最终状态。reference_trace仅是合格行为示例，不是运行日志。
